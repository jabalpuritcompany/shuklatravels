# Dancewala Studio — Website

Premium multi-page frontend for **Dancewala Studio**, a dance studio in Sector 46,
Gurugram. Built with HTML5, CSS3 and vanilla JavaScript — no framework, no jQuery,
no build-time dependencies in the shipped output.

**Domain:** https://dancewalas.com
**Status:** frontend complete · backend not yet integrated

---

## 1. What this is

A complete, deployable frontend that is also a **booking + payment prototype**:

- 54 static pages at clean, crawlable URLs
- Full booking wizard: service → details → login → schedule → summary → payment → result
- Login / register / forgot-password / dashboard / bookings screens
- Payment selection UI with **all gateways disabled by default**
- Payment success / failed / pending screens
- Enquiry form with WhatsApp hand-off
- JSON-LD (`DanceSchool`, `WebPage`, `BreadcrumbList`, `FAQPage`, `Service`)
- `sitemap.xml`, `robots.txt`, `site.webmanifest`, favicon, custom 404
- Email templates for customer confirmation and admin notification

Nothing is faked. No payment can be made, no account is created, no review or
rating is displayed, and no fee, timing, instructor name or award is invented.

## 2. How the site is built

The site is generated by a small Node script so that navigation, footer, schema
and 54 pages never drift out of sync.

```
tools/
  build.mjs              # writes every HTML file + robots.txt + sitemap.xml + manifest
  build-images.mjs       # converts _src/ masters into responsive WebP (needs sharp)
  site/
    config.js            # business NAP, socials, booking + payment + OAuth config
    data.js              # classes, choreography, team, gallery, reels, shorts, FAQs
    catalog.js           # flat service catalogue used by the booking wizard
    layout.js            # head, header, footer, schema, shared components
    components.js        # enquiry form, gallery grid, reels, shorts, contact blocks
    pages/               # one module per page or page group
```

**Build:**

```bash
node tools/build.mjs        # regenerate all HTML
node tools/build-images.mjs # regenerate responsive WebP (requires: npm i sharp)
```

`sharp` and `node_modules/` are dev-only and are **not** shipped to production.

### Why generated and not hand-written HTML?

The header, footer, breadcrumbs, schema and CTA blocks are identical across 54
pages. Editing them by hand guarantees drift. The generator writes plain static
HTML — the browser receives real markup, so navigation and copy are crawlable
and the site works with JavaScript disabled.

## 4. Deployment

Upload the repository root to `public_html` (cPanel) or your web root. Then rename
`htaccess.example` to `.htaccess` — it is shipped under a neutral name so local
static servers ignore it. It provides:

- HTTPS redirect
- `www` → bare-domain redirect
- GZIP / deflate compression
- Long-cache headers for CSS, JS and images
- `ErrorDocument 404 /404/`

## 5. Swapping in the real logo

The logo is currently a **clearly-marked placeholder**. To replace it:

1. Put the official files in `assets/images/logo/`:
   - `dancewala-studio-logo.svg` — full desktop wordmark
   - `dancewala-studio-logo-mark.svg` — compact mark for mobile
   - `favicon.svg` — favicon / app icon
2. Regenerate the raster icons:
   ```bash
   node -e "const s=require('sharp'),f=require('fs');
   s('assets/images/logo/favicon.svg').resize(180,180).png().toFile('assets/images/logo/apple-touch-icon.png')"
   ```
   (`favicon.ico` is generated the same way — see the note in section 9.)
3. Alt text is already correct everywhere: `Dancewala Studio - Dance Classes in Gurugram`.
4. Rebuild: `node tools/build.mjs`

**Colour palette** — the five brand colours live in one block at the top of
`assets/css/style.css` (`--primary`, `--secondary`, `--accent`, `--dark`,
`--light`). Retune them to match the official logo; nothing else needs to change.

## 6. Replacing the placeholder photography

Every image is AI-generated placeholder art with Indian dancers, chosen so each
service has a visually distinct photograph. Masters live in
`assets/images/_src/`; `tools/build-images.mjs` produces the responsive WebP.

To swap in real studio photography:

1. Drop full-resolution masters into `assets/images/_src/` using the same
   filenames (see the `JOBS` array in `tools/build-images.mjs`).
2. Run `node tools/build-images.mjs`.
3. Rebuild: `node tools/build.mjs`.

Because pages reference derivatives like
`assets/images/classes/bollywood-dance-classes-800.webp`, replacing a master
updates every page that uses it. No HTML needs editing.

**Licensing:** the generated placeholders are original artwork and carry no
third-party licence. If you source photos from Unsplash / Pexels / Pixabay
instead, keep a record of the licence for each file.

## 7. Backend integration map

Every integration point is marked in the code with a `FUTURE BACKEND INTEGRATION`
comment. Summary:

| Concern | File | What to change |
|---|---|---|
| Enquiry email / API | `assets/js/form-handler.js` | Set `EMAIL_ENDPOINT` |
| Service catalogue | `tools/site/catalog.js` | Replace JSON island with `GET /api/services` |
| Booking creation | `assets/js/booking.js` | `save()` → `POST /api/bookings` |
| Slot availability | `assets/js/booking.js` | Replace the static `slots` array |
| Coupon validation | `assets/js/booking.js` | Server-side `POST /api/coupons/validate` |
| Booking ID | `assets/js/booking.js` | Use the server-issued ID, not `generateId()` |
| Payment | `assets/js/payment.js` | Order + verify on the server; see the header comment |
| Payment gateways | `tools/site/config.js` | `PAYMENT_GATEWAYS` — keys stay server-side secrets |
| Google / Facebook / Instagram login | `assets/js/authentication.js` | Server-side token exchange only |
| Instagram feed | `assets/js/social.js` | Set `INSTAGRAM_FEED_ENDPOINT` |
| YouTube Shorts | `tools/site/data.js` | Add real video IDs to `SHORTS` |
| Analytics | `tools/site/config.js` | `GA_MEASUREMENT_ID`, `META_PIXEL_ID` |
| Transactional email | `email-templates/*.html` | Render server-side after payment verification |

**Payment must be verified on the server.** The browser must never be the thing
that decides a booking is paid. The correct order is documented in
`assets/js/payment.js` and section 4 of `SECURITY.md`.

## 9. Notes

- `favicon.ico` was generated by wrapping a 64px PNG in an ICO container (no
  ImageMagick ICO encoder was available). Regenerate it properly from the
  official logo when you swap the logo in.
- The booking wizard keeps progress in `sessionStorage` for the length of the
  visit. It contains no password and is cleared when the tab closes.
- Analytics and the Meta Pixel are configured but **disabled**. No third-party
  script loads, no cookie is set, so no consent banner is needed. If you enable
  either, add a consent mechanism first.
- No `AggregateRating` or fake review markup is present anywhere.
